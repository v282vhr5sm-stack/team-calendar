🛠️ 문제가 생겼을 때

① 캘린더가 “불러오기 실패”만 나오고 일정이 안 보여요

무료 서버가 멈췄을 수 있어요 (오래 안 쓰면 멈춤). 이렇게 다시 켜요:

  1. supabase.com → Sign in → Continue with GitHub
  2. 조직 공유캘린더 → 프로젝트 team-calendar 클릭
  3. “Project is paused” 같은 안내가 보이면 Restore project(복원) 버튼 → 몇 분 기다리기
  4. 캘린더를 다시 열면 끝. 데이터는 그대로 있어요.
② 캘린더 비밀번호를 잊었어요

로그인 화면 → “비밀번호를 잊었어요” → 이메일, 확인번호, 새 비밀번호 입력.

확인번호까지 잊었다면 Supabase에서 직접 바꿔요:

  1. Supabase → team-calendar 프로젝트 → 왼쪽 메뉴 SQL Editor (>_ 모양)
  2. 아래 내용을 복사해 붙여넣고, 새비밀번호와 이메일 부분만 바꾼 뒤 Run
update auth.users
set encrypted_password = extensions.crypt('새비밀번호', extensions.gen_salt('bf'))
where email = '대표이메일@naver.com';

“Success”가 나오면 새 비밀번호로 로그인하세요.

③ 일정을 실수로 지웠어요

지운 일정은 서버에 기록이 남아 있어서 되살릴 수 있어요. Supabase → SQL Editor에서:

1) 최근에 지운 일정 보기

select h.at as 지운시각, h.data->>'day' as 날짜, h.data->>'title' as 일정
from public.cal_history h
where h.tbl = 'cal_events' and h.op = 'DELETE'
order by h.at desc limit 50;

2) 최근 N시간 안에 지운 일정 모두 되살리기

아래의 '24 hours'를 필요하면 '3 days' 등으로 바꾸세요. 이미 있는 일정은 건너뛰어요.

insert into public.cal_events
select (jsonb_populate_record(null::public.cal_events,
         h.data || case when exists (select 1 from public.cal_categories c where c.id::text = h.data->>'category_id')
                        then '{}'::jsonb else '{"category_id": null}'::jsonb end)).*
from public.cal_history h
where h.tbl = 'cal_events' and h.op = 'DELETE' and h.at > now() - interval '24 hours'
on conflict (id) do nothing;

“destructive operations” 경고가 나오면 Run query를 누르세요. (되살리는 작업이라 안전해요)

④ 직원 링크가 다른 사람에게 새어 나갔어요
  • 🔗 공유 링크 → 그 링크의 링크 새로 만들기 → 예전 주소는 바로 막혀요. 새 링크를 직원에게 다시 보내세요.
  • 더 안전하게: 수정·보안에서 PIN(숫자 비밀번호)을 걸고 PIN은 따로 알려주세요.
  • 잠깐 막기만 하려면 ⏸ 멈추기.
⑤ 폰에서 예전 화면이 보이거나 이상해요
  • 크롬에서 사이트를 완전히 닫았다가 다시 열어요. (새 버전은 자동으로 적용돼요)
  • 카카오톡·네이버 앱 안에서 열린 창은 로그인이 풀릴 수 있어요. 크롬으로 열고 “홈 화면에 추가”해서 쓰세요.
⑥ 자동으로 서버 깨우기가 잘 되는지 확인하고 싶어요
  1. GitHub 저장소 → Actions 탭
  2. keep-alive 항목에 초록색 ✓가 3일 간격으로 있으면 정상이에요.
  3. 노란 안내로 “disabled(꺼짐)”가 보이면 Enable workflow를 누르세요.
